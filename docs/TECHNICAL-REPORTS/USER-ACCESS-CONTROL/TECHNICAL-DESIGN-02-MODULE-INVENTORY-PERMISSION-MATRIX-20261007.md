# گزارش فنی ۰۲ — Inventory ماژول‌ها و ماتریس اولیه Permission

**تاریخ:** 2026-10-07  
**دامنه:** استخراج ماژول‌ها و عملیات واقعی برای طراحی سیستم مرکزی کاربران  
**شاخه مستندات:** `docs/user-access-control-20261007`

## ۱. مبنای بررسی

مطابق سند محیط پروژه، `qa` مرجع تست و توسعه و `main` مرجع عملیاتی است.

در زمان بررسی:
- `qa` روی Commit `007b7cfe7755cb80f1bfa5b4266f70c5ba9c6b56` قرار دارد.
- `main` روی Commit `b5a641117400e8d2875b4530f8d46ad339a3d62f` قرار دارد.
- بنابراین بخشی از قابلیت‌های جدید کنترل کیفیت که در `main` موجودند هنوز در `qa` مرجع فعلی دیده نمی‌شوند. این اختلاف ثبت شد و به‌عنوان «اختلاف نسخه» در طراحی لحاظ می‌شود؛ بدون Merge یا تغییر کد.

## ۲. ساختار واقعی فعلی سامانه

از روی Navigation، فایل‌های Frontend و مستندات Freeze، دو حوزه اصلی عملیاتی شناسایی شد:

### A. جستجوی کل شهدا / All Martyrs

زیرقابلیت‌های واقعی:
1. جستجوی کل شهدا
2. فیلتر بر اساس اطلاعات هویتی و محل مزار
3. نمایش جزئیات
4. ویرایش رابط کاربری رکورد
5. خروجی Excel
6. افزودن نام تکی
7. افزودن نام گروهی
8. بازبینی اطلاعات ثبت اولیه
9. تأیید و ثبت نهایی مسیر ثبت جدید

**نکته مهم:** ویرایش موجود در All Martyrs در کد فعلی برای نتایج جستجو با تغییر آبجکت جاری و نمایش مجدد انجام می‌شود و از شواهد بررسی فعلی، آن را نباید با «ویرایش پایدار منبع عملیاتی» یکی فرض کرد. بنابراین Permission آن در مدل آینده باید جداگانه تعریف شود.

### B. مدیریت و بهسازی سنگ مزار

منوی فعلی شامل:
1. جستجوی شهید
2. ثبت اطلاعات
3. تأیید ثبت اطلاعات
4. گزارش‌های آماری

در این حوزه عملیات واقعی موجود شامل:
- مشاهده و جستجو
- مشاهده جزئیات
- ثبت رکورد جدید در `martyrs`
- ویرایش رکورد موجود
- تغییر وضعیت/مرحله
- تأیید رکورد
- خروجی Excel
- مشاهده آمار
- دریافت آمار زنده از Supabase

## ۳. بخش کنترل کیفیت داده

در نسخه عملیاتی جدید، کنترل کیفیت به‌صورت یک لایه مستقل روی منوی مدیریت و بهسازی طراحی شده است.

عملیات آن:
- مشاهده شاخص‌های کیفیت
- مشاهده رکوردهای دارای مشکل
- ایجاد پیشنهاد اصلاح
- ویرایش پیشنهاد اصلاح
- ارجاع برای اصلاح
- بررسی توسط Reviewer
- تأیید نهایی
- اعمال کنترل‌شده اصلاح روی `martyrs`
- ثبت اطلاعات Audit مرتبط با گردش اصلاح

این بخش باید کاملاً زیر سیستم مرکزی کاربران قرار گیرد.

## ۴. آمار و گزارش

آمار یک Permission مستقل است و نباید با Permission مشاهده رکوردها یکی شود.

مجوزهای مورد نیاز:
- `statistics.view`
- `statistics.export` در صورت فعال بودن خروجی
- در آینده مجوزهای مدیریتی برای گزارش‌های حساس

نکته: صفحه آمار فعلی در نسخه‌های مختلف پروژه baseline و Live Statistics داشته است؛ بنابراین «مشاهده آمار» به معنی اجازه تغییر منبع آماری نیست.

| مشاهده‌گر | ✓ | — | — | — | — | — | — | خود |

| کارشناس بهسازی | ✓ | ✓ | ✓ | — | محدود | — | — | حوزه |

## ۷. اصل مهم درباره Delete

در هیچ نقش عادی، `delete` نباید به‌صورت پیش‌فرض فعال باشد.

برای داده‌های عملیاتی، ترجیح معماری:
- غیرفعال‌سازی/ابطال
- Soft Delete در صورت نیاز
- یا Workflow مدیریتی با Audit

به‌جای حذف فیزیکی رکورد.

## ۸. اصل مهم درباره Admin

`admin` به‌صورت خودکار نباید مساوی `approve` یا `martyrs.edit` باشد.

هر دسترسی حساس باید Permission مستقل داشته باشد.

## ۹. Audit رویدادهای اجباری

حداقل این عملیات باید Audit شوند:

- Login / Logout
- شکست ورود
- ایجاد/غیرفعال‌سازی User
- تغییر Role
- تغییر Permission
- مشاهده/خروجی داده حساس در صورت سیاست نهایی
- Create
- Edit
- Change Stage
- Approve
- Reject
- Quality Review
- Quality Apply
- تغییر تنظیمات حساس

برای عملیات داده‌ای حساس، ثبت Before/After و شناسه رکورد ضروری است.

## ۱۰. مواردی که هنوز نباید نهایی فرض شوند

1. نام نهایی Roleهای سازمانی.
2. Permissionهای جزئی تمام صفحات فرعی.
3. محدوده دقیق داده‌ای هر Permission؛ مثلاً همه قطعات یا قطعات خاص.
4. مدل نهایی Login و بازیابی رمز.
5. امکان MFA.
6. مدل Session و Timeout.
7. مدل دقیق Audit Storage.
8. Policy/RLS نهایی.
9. نحوه اعمال Permission در Backend/Edge Function.
10. وضعیت نسخه QA در برابر قابلیت‌های جدیدی که در main قرار گرفته‌اند.

## ۱۱. تصمیم مرحله‌ای

در این مرحله **ماتریس Permission اولیه قابل استفاده برای ادامه طراحی است، اما هنوز Schema/Auth/RLS نهایی نیست.**

مرحله بعد:

**طراحی دقیق Roleها و Permissionها + Scope دسترسی داده**

و پس از آن:

**طراحی Authentication / Session / User Lifecycle**

سپس:

**طراحی Audit Log و Authorization/RLS**

هیچ تغییر عملی در Supabase یا داده واقعی در این مرحله انجام نشده است.
